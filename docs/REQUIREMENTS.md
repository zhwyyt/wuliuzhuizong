# Requirements Brainstorming

## 背景判断

目标是在 `I:\githubtemple\wuliugenzong` 从零重做一个 GPS/物流位置监控系统。`traccar-server` 和 `traccar-web` 只作为产品结构与交互参考，不作为代码来源，也不允许写入。

## 最可能的产品定位

这是一个面向中国物流、配送、项目制外勤或施工运输场景的项目级位置监控平台。主要数据源不是车载硬件，而是 Android 手机 App 定时上报定位。

## 核心用户

- 调度管理员：查看所有项目实时分布、异常、在线人员和轨迹。
- 项目负责人：只关注某个项目下的人员/设备。
- 一线人员：通过 Android App 绑定项目并持续上报位置。
- 会议/值班室观众：通过大屏查看全局运行状态。

## MVP 必须覆盖

- 登录：先采用演示账号或简化权限。
- 项目管理：创建项目、查看项目列表。
- 成员/设备管理：设备归属到项目，手机作为默认设备形态。
- 定位上报：Android App 或模拟器向后端上报位置点。
- 实时查看：Web 能按项目或全部项目查看最新位置。
- 轨迹回放：按设备查看历史位置点。
- 大屏总览：展示项目总数、在线人数、今日活跃、异常数量、地图分布和项目切换。

## 后续扩展预留

- PostgreSQL + PostGIS 持久化。
- 高德地图 Web JS API。
- Android 高德定位 SDK 和后台保活。
- WebSocket 实时推送。
- 项目成员角色、权限边界、电子围栏、告警规则、任务、签到、导航。

## 低风险假设

- 首个 MVP 可以使用内存数据仓库，先证明产品闭环。
- 高德地图可先以适配边界和地图占位实现，真实 Key 后接入 SDK。
- Android 端按用户更正使用 Android Studio 原生工程，不使用 Flutter。
- 登录先用演示 token，不阻塞主流程。

## 暂不处理

- 真实账号体系和密码安全。
- 真实 PostgreSQL/PostGIS 部署。
- 生产级 Android 后台定位策略。
- 复杂告警规则、电子围栏和报表导出。
- 多租户隔离和审计合规。

## 成功标准

- 本地后端可启动并返回核心 API。
- Web 管理端可登录、查看项目、筛选项目、查看实时点和轨迹。
- 大屏页可查看全项目和单项目概览。
- Android Studio 能打开移动端工程，代码中具备定位上报主流程。
- 文档说明当前完成度、运行方式、未完成内容和下一阶段计划。
